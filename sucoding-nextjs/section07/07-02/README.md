# 📌 [SSR]

> **한 줄 요약**: SSR의 이론

---

## 💡 핵심 학습 내용 (Key Concepts)

### 1. [개념]

CSR의 단점을 보완하기 위해 SSR방식이다. Server Side Rendering(SSR)방식은 서버에서 초기 콘텐츠를 생성해서 클라이언트로 전송하는 방식이다. 초기 콘텐츠를 서버에서 생성하기 때문에 클라이언트, 서버, 데이터베이스가 필요하다.

### 2. [동작 방식]

1. 사용자가 웹사이트에 접속하면 클라이언트는 Server에 GET 요청을 보낸다.
2. Server는 요청을 받으면 데이터베이스에 쿼리를 보내 필요한 데이터를 가져온다.
3. 데이터베이스에서 데이터를 받아오면 서버는 데이터를 사용해 완성된 HTML을 생성한다.
4. 서버가 완성된 HTML을 클라이언트로 반환하면 사용자는 즉시 콘텐츠를 볼 수 있게 된다.
5. 이 시점에서 페이지는 `content loaded not interactive`로 콘텐츠는 보이지만 상호작용은 불가능한 상태이다.
6. 그 다음으로 서버는 JS 번들 파일을 클라이언트로 전송한다.
7. JS 번들 파일을 다 다운받으면 Hydrate(HTML 요소에 이벤트를 연결하는 것)과정을 거치게 된다.
8. 모든 Hydrate가 완료되면 페이지는 모두 다 완성된다.

이에 서버에서 완성된 HTML을 만들어 보내기 때문에 초기 콘텐츠의 표시가 빠르고 검색엔진이 콘텐츠를 제대로 읽을 수 있어 SEO에 유리하다. 하지만 서버에서 매번 HTML 을 생성해야 하므로 서버 부하가 증가하고 Hydrate 과정까지 완료되어야 완전한 상호작용이 가능해진다라는 단점을 가지고 있다.
