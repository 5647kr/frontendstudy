## 💡 핵심 학습 내용 (Key Concepts)

### 1. [개념]

SSG는 빌드시점의 데이터만 사용할 수 있기 때문에 실시간으로 변하는 데이터를 보여줄 수 없다. 이러한 한계를 해결한 것이 바로 Incremental Static Regenertaion(ISR)이다. `점진적 정적 재생성`이라 불린다. 이는 SSG의 빠른 속도는 유지하되, 필요한 페이지만 주기적으로 업데이트 한다.

- build 타임
- run 타임

### 2. [동작 방식]

`build 타임`

1. 웹 사이트를 배포하기 전 개발자가 빌드 명령어를 실행하는 시점이다.
2. 빌드 프로세스가 시작되면 빌드 시스템은 데이터베이스에 쿼리를 보내 필요한 모든 데이터를 가져온다.
3. 이렇게 가져온 데이터를 가지고 모든 페이지에 HTML을 미리 생성한다.
4. 이때 revalidate 옵션을 추가한다. 이는 설정한 시간마다 재생성을 뜻한다.
4. 생성된 모든 HTML, CSS, JS 번들 파일은 CDN에 업로드된다.

위의 과정은 배포 시점에 딱 한 번만 실행된다.

`run 타임`

1. 사용자가 웹사이트에 접속하면 클라이언트는 CDN에 GET 요청을 보낸다.
2. 이 시점에서 화면은 아직 비어있다.
3. CDN은 미리 빌드된 HTML과 JS 번들을 함께 클라이언트로 반환한다.
4. 사용자는 `content loaded not interactive`로 콘텐츠는 보이지만 상호작용은 불가능한 상태의 페이지를 받게 된다.
5. 이후 JS가 실행되고 로드가 되게 되면 Hydration이 발생되게 되고 완전한 페이지를 사용할 수 있는 상태가 된다.

### 3. [정리]

ISR의 장점
1. SSG처럼 빠른 성능을 유지한다.
2. 전체 사이트를 다시 빌드할 필요가 없다.
3. 어느 정도 최신 상태를 유지할 수 있다.
4. 사용자는 업데이트 과정을 전혀 느낄 수 없다

하지만 완전한 실시간 데이터 제공은 불가능하다

### 4. [지금까지의 최종 정리]

- CSR
  - SEO가 중요하지 않고 사용자 인터렉션이 많은 관리자 대시보드나 내부 툴에 적합하다.
- SSR
  - 실시간 데이터가 중요하고 SEO도 필요한 전자상거래 사이트나 소셜 미디어 피드에 적합하다.
- SSG
  - 내용이 거의 변하지 않는 블로그, 문서 사이트, 마케팅 랜딩 페이지에 적합하다.
-ISR
  - 콘텐츠가 주기적으로 업데이트 되지만 실시간일 필요는 없는 뉴스 사이트나 제품 목록 페이지에 적합하다.
